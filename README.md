# NaviComputer

Repository for **Kakeman89s Datacron**, a [Foundry Virtual Tabletop](https://foundryvtt.com/) module that helps **Star Wars 5e (SW5e)** games plan hyperspace travel: route estimates, travel time, consumables, and optional piloting checks.

The installable module lives in [`kakeman89s-datacron/`](kakeman89s-datacron/).

---

## What this module is for

- **Hyperspace planning at the table** — Pick an origin and destination from curated planet data, then get travel time and rough resource needs (fuel, food, supplies) without leaving Foundry.
- **Basic hyperspace estimates** — Region-to-region travel times from a matrix (broad galactic averages, not individual hyperlanes). Advanced lane-graph routing is currently disabled while the map data is refined.
- **Starship-aware estimates** — Optional ship selection feeds crew size for provision estimates when the actor data matches SW5e conventions.
- **Piloting checks** — Roll the pilot’s skill (default `pil`, with configurable fallback) as a **private GM roll** so the table does not see the full result in chat.

It does **not** replace the GM’s judgment, move tokens, or enforce strict SW5e rules for every edge case. It is a navigation aid and consistency helper.

## Installation

1. Copy or symlink the `kakeman89s-datacron` folder into your Foundry user `Data/modules/` directory, **or** install from a manifest URL if you publish releases.
2. In Foundry: **Add-on Modules** → enable **Kakeman89s Datacron**.
3. Launch a world that uses **dnd5e** (ideally with SW5e active).

## How to use it

### Opening the Datacron

- **Gamemasters** — Use the **scene controls** (token tools): click the **route** icon labeled for opening the Datacron. The app window opens and can be moved and resized like other Foundry applications.

### Calculating a route

1. **Origin** and **Destination** — Type or pick worlds from the planet list (loaded from module data). The list is built from **`Star Wars Galaxy Map Grid Coordinates.xlsx`** (primary for `grid` / `sector` / `region`) merged with narrative fields from the module’s JSON; spreadsheet blanks fall back to JSON for those fields on matching names.
2. **Pilot** — Choose an actor (character or NPC) for piloting rolls. Required only if you plan to roll.
3. **Ship (optional)** — Select a starship-type actor if you want crew-based food estimates.
4. Click **Calculate Route**.

Read the **Results** panel for travel hours, regions, route summary, suggested piloting DC, and warnings.

### Advanced lane graph

Advanced hyperlane routing is temporarily disabled in the Foundry UI. The supporting graph data and scripts remain in the repository for map-data work:

- `data/hyperspace-routes.json` can still be regenerated by **`scripts/build-hyperspace-graph.py`** from **StarWarsMap** lane chains, root GeoJSON (non-suppressed features), `planets.json`, `route-tier-overrides.json`, and `hyperspace-routes.hand.json`.
- **`python scripts/validate-hyperspace-routes.py`** still validates graph endpoints, reports connectivity, and emits the route sanity report used during graph refinement.
- Runtime calculations currently use Basic regional estimates only.

### Piloting check

1. Calculate a route first.
2. Select a **Pilot**.
3. Click **Roll Piloting Check**.

The roll is sent using the system’s skill roll, in **private GM** mode by default. The Datacron window is kept in front after the roll where possible.

### Module settings

Configure under **Configure Settings → Module Settings → Kakeman89s Datacron**:

| Setting | Purpose |
|---------|--------|
| **Fuel Per Hour** / **Food Per Crew Per Day** | Scale resource estimates from travel duration and crew. |
| **Piloting fallback skill** | Skill id used if `pil` / `piloting` are missing on the pilot (default `acr`). |
| **Enable Random Events** / **Random Event Chance** | Reserved for future travel events (hooks exist in settings). |
| **Debug Logging** | Extra client-side logging for troubleshooting. |

World scope vs client scope follows each setting’s definition in Foundry.

## Project layout (high level)

| Path | Role |
|------|------|
| `kakeman89s-datacron/module.json` | Foundry manifest |
| `kakeman89s-datacron/data/planets.json` | Planet list (galaxy spreadsheet + JSON merge; see `scripts/merge-planet-data.py`) |
| `scripts/merge-planet-data.py` | Regenerates `planets.json` from repo-root `Star Wars Galaxy Map Grid Coordinates.xlsx` + prior JSON enrichment |
| `Galactic Map.jpg` (repo root) | Reference artwork for calibrating control points / grid-to-geo (not georeferenced; see `docs/hyperspace-coordinate-transform.md`) |
| `hyperspace_singlepart_new.json` (repo root) | GeoJSON hyperlanes (connectors and routes not overridden by StarWarsMap) |
| `kakeman89s-datacron/data/starwarsmap/hyperlanes_db.json` | Authoritative named-lane world order (StarWarsMap); see `docs/hyperspace-coordinate-transform.md` |
| `scripts/build-hyperspace-graph.py` | Builds `hyperspace-routes.json` from StarWarsMap + GeoJSON + planets + tier overrides |
| `scripts/validate-hyperspace-routes.py` | Validates route endpoints against `planets.json` |
| `docs/hyperspace-coordinate-transform.md` | How planet coordinates relate to GeoJSON |
| `kakeman89s-datacron/data/hyperspace-control-points.json` | Affine `(x,y)→(lon,lat)` when ≥3 points; bootstrap with `python scripts/build-hyperspace-graph.py --suggest-control-points` |
| `kakeman89s-datacron/data/grid-to-geo.json` | Optional per-cell CRS84 overrides keyed by grid (e.g. `K-12`) |
| `kakeman89s-datacron/data/hyperspace-routes.json` | Hyperlane segments for Advanced mode (generated + hand merge) |
| `kakeman89s-datacron/data/hyperspace-routes-catalog.json` | Optional authoring list of named routes / tiers (reference only) |
| `kakeman89s-datacron/scripts/` | Application logic, routing, rolls, settings |
| `kakeman89s-datacron/templates/` | Handlebars UI |
| `kakeman89s-datacron/lang/en.json` | English strings |
