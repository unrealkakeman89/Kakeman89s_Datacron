# NaviComputer

Repository for **SW5e Nav Computer**, a [Foundry Virtual Tabletop](https://foundryvtt.com/) module that helps **Star Wars 5e (SW5e)** games plan hyperspace travel: route estimates, travel time, consumables, and optional piloting checks.

The installable module lives in [`sw5e-nav-computer/`](sw5e-nav-computer/).

---

## What this module is for

- **Hyperspace planning at the table** — Pick an origin and destination from curated planet data, then get travel time and rough resource needs (fuel, food, supplies) without leaving Foundry.
- **Two calculation modes**
  - **Basic** — Region-to-region travel times from a matrix (broad galactic averages, not individual hyperlanes).
  - **Advanced** — Shortest path on a **Legends-oriented hyperlane graph**: **StarWarsMap** (`data/starwarsmap/hyperlanes_db.json`) defines authoritative **named-lane chains** (consecutive hops); root **GeoJSON** still supplies other lines (e.g. regional connectors) and is not used to “chord” over routes StarWarsMap already lists. Planet alignment uses control points / grid-to-geo (see `docs/hyperspace-coordinate-transform.md`). Pairs with no graph path use **Advanced regional fallback** (not Basic), with a clear notice.
- **Starship-aware estimates** — Optional ship selection feeds crew size (for provisions) and hyperdrive class (Advanced time multiplier) when the actor data matches SW5e conventions.
- **Piloting checks** — Roll the pilot’s skill (default `pil`, with configurable fallback) as a **private GM roll** so the table does not see the full result in chat.

It does **not** replace the GM’s judgment, move tokens, or enforce strict SW5e rules for every edge case. It is a navigation aid and consistency helper.

## Installation

1. Copy or symlink the `sw5e-nav-computer` folder into your Foundry user `Data/modules/` directory, **or** install from a manifest URL if you publish releases.
2. In Foundry: **Add-on Modules** → enable **SW5e Nav Computer**.
3. Launch a world that uses **dnd5e** (ideally with SW5e active).

## How to use it

### Opening the Nav Computer

- **Gamemasters** — Use the **scene controls** (token tools): click the **route** icon labeled for opening the Nav Computer. The app window opens and can be moved and resized like other Foundry applications.

### Calculating a route

1. **Origin** and **Destination** — Type or pick worlds from the planet list (loaded from module data). The list is built from **`Star Wars Galaxy Map Grid Coordinates.xlsx`** (primary for `grid` / `sector` / `region`) merged with narrative fields from the module’s JSON; spreadsheet blanks fall back to JSON for those fields on matching names.
2. **Pilot** — Choose an actor (character or NPC) for piloting rolls. Required only if you plan to roll.
3. **Ship (optional)** — Select a starship-type actor if you want crew-based food estimates and (in Advanced mode) hyperdrive-based travel time scaling.
4. Click **Calculate Route**.

Read the **Results** panel for travel hours, regions, route summary, suggested piloting DC, and warnings. In **Advanced** mode you will also see the **world-by-world path**, **lane names per hop** (charted lanes vs dimmed **transit corridors**), and the **hyperdrive multiplier** used.

### Advanced mode and coverage

- Advanced mode uses `data/hyperspace-routes.json`, regenerated by **`scripts/build-hyperspace-graph.py`** from **StarWarsMap** lane chains, root GeoJSON (non-suppressed features), `planets.json`, `route-tier-overrides.json`, and `hyperspace-routes.hand.json`. The builder adds **transit corridors** and marks **regional connectors** so every world with parseable coordinates stays on one connected graph. **`python scripts/validate-hyperspace-routes.py`** checks endpoints, reports worlds without parseable grid/coordinates, and confirms one undirected component.
- **Legends tiers vs. the graph** — Settings cap which **optional** lane tiers are used, but **essential connectivity** segments (transit corridors, regional connectors) always stay in the graph. Piloting DC adds **+1 per hop**, plus summed **lane DC bonuses** and optional **extra DC per tier-5 hop** (world setting).
- If the lane file fails to load or a path is still missing, Advanced mode uses a **regional single-hop estimate** (still Advanced, not Basic), with a note in **Warnings**.

### Piloting check

1. Calculate a route first.
2. Select a **Pilot**.
3. Click **Roll Piloting Check**.

The roll is sent using the system’s skill roll, in **private GM** mode by default. The Nav Computer window is kept in front after the roll where possible.

### Module settings

Configure under **Configure Settings → Module Settings → SW5e Nav Computer**:

| Setting | Purpose |
|---------|--------|
| **Calculation Mode** | **Basic** or **Advanced** (see above). |
| **Advanced — maximum hyperspace tier** | Lanes above this tier are excluded from pathfinding (default 3). |
| **Advanced — include obscure routes** | Allows lanes marked obscure in the data (default off). |
| **Advanced — extra DC per tier-5 hop** | Optional add-on to piloting DC for each hop on a tier-5 lane (default 0). |
| **Fuel Per Hour** / **Food Per Crew Per Day** | Scale resource estimates from travel duration and crew. |
| **Piloting fallback skill** | Skill id used if `pil` / `piloting` are missing on the pilot (default `acr`). |
| **Enable Random Events** / **Random Event Chance** | Reserved for future travel events (hooks exist in settings). |
| **Debug Logging** | Extra client-side logging for troubleshooting. |

World scope vs client scope follows each setting’s definition in Foundry.

## Project layout (high level)

| Path | Role |
|------|------|
| `sw5e-nav-computer/module.json` | Foundry manifest |
| `sw5e-nav-computer/data/planets.json` | Planet list (galaxy spreadsheet + JSON merge; see `scripts/merge-planet-data.py`) |
| `scripts/merge-planet-data.py` | Regenerates `planets.json` from repo-root `Star Wars Galaxy Map Grid Coordinates.xlsx` + prior JSON enrichment |
| `Galactic Map.jpg` (repo root) | Reference artwork for calibrating control points / grid-to-geo (not georeferenced; see `docs/hyperspace-coordinate-transform.md`) |
| `hyperspace_singlepart_new.json` (repo root) | GeoJSON hyperlanes (connectors and routes not overridden by StarWarsMap) |
| `sw5e-nav-computer/data/starwarsmap/hyperlanes_db.json` | Authoritative named-lane world order (StarWarsMap); see `docs/hyperspace-coordinate-transform.md` |
| `scripts/build-hyperspace-graph.py` | Builds `hyperspace-routes.json` from StarWarsMap + GeoJSON + planets + tier overrides |
| `scripts/validate-hyperspace-routes.py` | Validates route endpoints against `planets.json` |
| `docs/hyperspace-coordinate-transform.md` | How planet coordinates relate to GeoJSON |
| `sw5e-nav-computer/data/hyperspace-control-points.json` | Affine `(x,y)→(lon,lat)` when ≥3 points; bootstrap with `python scripts/build-hyperspace-graph.py --suggest-control-points` |
| `sw5e-nav-computer/data/grid-to-geo.json` | Optional per-cell CRS84 overrides keyed by grid (e.g. `K-12`) |
| `sw5e-nav-computer/data/hyperspace-routes.json` | Hyperlane segments for Advanced mode (generated + hand merge) |
| `sw5e-nav-computer/data/hyperspace-routes-catalog.json` | Optional authoring list of named routes / tiers (reference only) |
| `sw5e-nav-computer/scripts/` | Application logic, routing, rolls, settings |
| `sw5e-nav-computer/templates/` | Handlebars UI |
| `sw5e-nav-computer/lang/en.json` | English strings |
